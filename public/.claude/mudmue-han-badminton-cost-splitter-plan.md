# Mudmue Han (หาร) — Badminton Cost Splitter
## Final Task Plan — พร้อม Implement

---

## 1. ภาพรวมปัญหา
ค่าลูกแบดรู้ได้แค่หลังเล่นจบ (ต้องนับลูกจริง) ต่างจากค่าคอร์ทที่รู้ล่วงหน้า ต้องมีเมนูคำนวณแยกหลังเล่น หารเท่ากันโดย default แต่รองรับ override จำนวนลูกรายคนเมื่อเล่นลูกไม่เท่ากัน (เคสมาไม่เต็มเวลา → phase 2)

## 2. Decisions ที่ยืนยันแล้ว (quick reference)
| เรื่อง | ข้อสรุป |
|---|---|
| ปัดเศษ | ปัดขึ้นเสมอ ส่วนต่างเป็นของคนจัด/กองกลาง |
| ชั่วโมงต่อคน | **ยกไป phase 2** — เฟสนี้ถือว่าทุกคนอยู่ครบทั้งก๊วน ค่าคอร์ทหารเท่ากันหมด |
| ลูกต่อคน | กรอกจำนวนลูกที่ร่วมหารได้ ค่าเริ่มต้น = ครบทุกลูกที่ใช้ทั้งวัน |
| Profile คน | shared store เดียวกับ Mudmue Chok, เพิ่มจากเมนูไหนก็ sync กัน |
| ลบคนออกจาก Profile | ห้ามลบถ้ามีประวัติผูกอยู่ — archive/ซ่อนแทน |
| Validation เกินยอดจริง | เตือนอย่างเดียว ไม่บล็อกการกดสรุป |
| ประวัติ session | เก็บเป็น JSON (เบา ~1-2KB/session) ไม่เก็บรูปภาพ |
| แชร์/ใบเสร็จ | generate รูปสดตอนกดแชร์เท่านั้น ไม่เก็บถาวร |
| QR รับเงิน (MVP) | อัปโหลดรูป QR พร้อมเพย์ครั้งเดียวใน Settings, ปุ่มเล็กเปิด modal โชว์ |
| QR แบบฝังยอด | ขยายทีหลัง (ใช้ `promptpay-qr` + ยอดต่อคน) |

## 3. ค่าคอร์ท — ดีไซน์สุดท้าย (ป้ายราคา "ชม." ลากไปแปะบนคอร์ท)

**คอนเซปต์ (ยืนยันแล้วจาก mockup):** "ชม." แต่ละอันคือ **ป้ายราคาแยกชิ้น** ไม่ได้ผูกกับคอร์ทใดคอร์ทหนึ่งตายตัว — สร้างป้ายไว้ล่วงหน้า (เช่น "ชม.แรก 120 บาท/ชม.", "ชม.ที่ 2 100 บาท/ชม.") แล้ว **ลากป้ายไปแปะบนไอคอนคอร์ทที่ใช้ช่วงราคานั้นจริง** คอร์ทหนึ่งแปะได้หลายป้าย (เล่นหลายชั่วโมงคนละราคา) และป้ายเดียวกันแปะกับหลายคอร์ทพร้อมกันได้ (คอร์ทที่เล่นพร้อมกันในชั่วโมงเดียวกันก็ใช้ราคานั้นเหมือนกัน)

**หน้าจอ:**
- แถวไอคอนคอร์ทตัวใหญ่ เรียงตามจำนวนคอร์ทที่มี เลื่อนดูได้ถ้าเกินจอ มีปุ่ม "+ เพิ่มคอร์ท" ท้ายแถว และปุ่มลบที่มุมแต่ละคอร์ท (มีอย่างน้อย 1 คอร์ทเสมอ)
- ใต้แถวคอร์ท: รายการ "การ์ดชม." แต่ละใบมีชื่อช่วง (แก้ไขได้), ราคา/ชม., จำนวนชั่วโมงของช่วงนั้น — ลาก (HTML5 drag) ไปวางบนคอร์ทที่ต้องการ
- **ทางเลือกสำรองกรณีลากไม่สะดวก** (มือถือหน้างาน แดดจ้า/มือเหงื่อ): แตะปุ่ม grip ที่การ์ดชม. เพื่อ "เลือก" แล้วแตะคอร์ทเป้าหมาย ก็ผูกให้เหมือนกับลาก — ต้องมีทั้งสองทางเสมอ ไม่ใช่มีแค่ drag
- ในคอร์ทแต่ละอันแสดงป้ายเล็กๆ ของทุกช่วงราคาที่แปะอยู่ แตะป้ายเพื่อลบออกจากคอร์ทนั้น (ไม่ได้ลบป้ายต้นฉบับ)
- ใต้ไอคอนคอร์ทแต่ละอันโชว์ยอดรวมของคอร์ทนั้น (บวกจากทุกป้ายที่แปะ)
- ผลรวมค่าคอร์ททั้ง session = รวมยอดของทุกคอร์ท

## 4. Data Model (ฉบับสุดท้าย)
```
Profile {
  id, name
  archived: boolean        // true = ซ่อนจากลิสต์เลือกคนใหม่ แต่ history เก่ายังอ้างอิงได้
}

RateTier {                  // "ป้ายราคา ชม." — สร้างไว้ล่วงหน้า ใช้ซ้ำได้กับหลายคอร์ท
  id
  label: string             // เช่น "ชม.แรก" แก้ไขได้ ไม่บังคับ
  pricePerHour: number
  hours: number              // ปกติ 1 แต่ปรับได้
}

Court {
  id
  index: number              // ลำดับคอร์ทที่แสดงผล (คอร์ท 1, 2, ...)
  tierIds: string[]          // รายชื่อ RateTier ที่ถูก "แปะ" ไว้บนคอร์ทนี้
}

Session {
  id, date
  tiers: RateTier[]
  courts: Court[]                 // เพิ่ม/ลบคอร์ทได้อิสระ
  shuttlePricePerPiece: number
  shuttleUsedCount: number        // stepper — ยอดรวมลูกที่ใช้จริงทั้งวัน
  attendees: AttendeeEntry[]
}

AttendeeEntry {
  profileId
  courtHours: number | null       // ชั่วโมงจริงที่อยู่ — null = เต็มเวลา (default = sessionDurationHours)
  shuttleCount: number | null     // จำนวนลูกที่ร่วมหาร — null = ครบทุกลูก (default = shuttleUsedCount)
}

Settings {
  paymentQrImage: string          // base64 รูป QR พร้อมเพย์ (MVP: static image)
}
```

**สูตรคำนวณ:**
```
courtCost(court)   = Σ tierIds ของคอร์ทนั้น → (tier.pricePerHour × tier.hours)
courtSubtotal      = Σ courtCost(court) ทุกคอร์ท
courtHours(court)  = Σ tierIds ของคอร์ทนั้น → tier.hours          // แสดงบนการ์ดคอร์ท
sessionDurationHours = max( courtHours(court) ทุกคอร์ท )          // คอร์ทที่จองยาวที่สุด = เวลาเต็มของก๊วน
                                                                  // (คอร์ทเล่นพร้อมกัน เวลาจึงไม่บวกกัน)
                                                                  // แสดงผลอย่างเดียว ไม่ได้ใช้หารในเฟสนี้

personCourtShare_i  = courtSubtotal ÷ จำนวนคนที่มา                 // phase 1: ทุกคนอยู่ครบทั้งก๊วน
personShuttleCost_i = (attendee.shuttleCount ?? shuttleUsedCount) ÷ Σ(ทุกคน shuttleCount ที่ใช้จริง) × shuttleSubtotal
personTotal_i        = ceil(personCourtShare_i + personShuttleCost_i)   // ปัดขึ้นเสมอ
```

## 5. UI Standards ที่ใช้ทั้งแอป
- ปุ่มกด/ไอคอนต่างๆ ต้องมีพื้นที่แตะขั้นต่ำ **44×44px**
- ทุกปุ่มไอคอนต้องมี `aria-label` (เช่น "ลบคอร์ทนี้", "เพิ่มคอร์ท", "เลือกช่วงราคานี้")
- ตัวเลขราคาที่กรอกได้ ต้องมีสัญลักษณ์ **฿** ติดกับตัวเลขเสมอ
- ค่าเริ่มต้นทุก section เรียบง่ายที่สุด ไม่ preset ตัวอย่างซับซ้อนมาให้ตั้งแต่แรกเห็น
- Subtotal/summary ทุกจุดอัปเดตทันทีแบบ real-time
- ทุกจุดที่ใช้ drag-and-drop **ต้องมีทางเลือกแบบแตะ-เลือก-แล้วแตะเป้าหมาย** เป็นทางสำรองเสมอ (accessibility + ความน่าเชื่อถือหน้างาน)

## 6. หน้าจอ/Flow อื่นๆ
1. **เลือกคนมาวันนี้** — ดึงจาก Profile กลาง (ไม่แสดงคน archived), เพิ่มชื่อใหม่ได้แล้ว sync กลับเข้า Profile
2. **ปรับจำนวนลูกเฉพาะคน (optional)** — ต่อคน ใส่จำนวนลูกที่ร่วมหาร ค่าเริ่มต้น = null (= ครบทุกลูกที่ใช้ทั้งวัน) · ชั่วโมงรายคนรอ phase 2
3. **สรุปผล** — breakdown ต่อคน (ค่าคอร์ท/ค่าลูกแยก), แสดงส่วนต่างที่ปัดขึ้น, warning (ไม่ block) ถ้า override เกินยอดจริง
4. **QR รับเงิน** — ปุ่มเล็กที่หน้าสรุป เปิด modal โชว์ QR ที่ตั้งค่าไว้ล่วงหน้า
5. **แชร์** — ปุ่ม copy ข้อความสรุป + generate รูปใบเสร็จสดตอนกดแชร์เท่านั้น

## 7. Task Plan

| Phase | งาน | รายละเอียด |
|---|---|---|
| **1. Shared Profile store** | แยก Profile เป็น store กลาง | refactor ลิสต์คนของ Mudmue Chok ให้ใช้ร่วมกับ Han ได้, เพิ่ม field `archived` + guard ห้ามลบถ้ามี session ผูกอยู่ |
| **2. Tier + Court data & calc engine** | โครงสร้างข้อมูล RateTier/Court + สูตรคำนวณ | CRUD ป้ายราคา, courts[] พร้อม tierIds[], คำนวณ courtCost ต่อคอร์ท, courtSubtotal, sessionDurationHours ตาม section 4 |
| **3. Tier chips UI** | การ์ด "ชม." แก้ไขได้ + ลากได้ | เพิ่ม/ลบ/แก้ไขป้ายราคา (label, ฿/ชม., จำนวนชม.), ตั้ง draggable + drag handle พร้อม aria-label |
| **4. Court builder UI** | คอร์ทตัวใหญ่ + จุดวาง (drop target) | แถวไอคอนคอร์ท (เพิ่ม/ลบคอร์ทได้), รับ drop จากป้ายราคา, โหมดแตะ-เลือก-แตะคอร์ทเป็นทางสำรอง, แสดงป้ายที่แปะอยู่ + ยอดรวมต่อคอร์ท |
| **5. Shuttle input** | ราคา/ลูก + stepper จำนวนที่ใช้ | แสดง subtotal สด |
| **6. People + attendance** | เลือกคนมาวันนี้ + เพิ่มคนใหม่ | toggle เลือกคน, เพิ่มชื่อใหม่ sync กลับ Profile |
| **7. Per-person override** | UI ปรับยอดเฉพาะคน | ใส่จำนวนลูกที่ร่วมหารต่อคน, badge "ค่าเริ่มต้น"/"ปรับแล้ว" (ชั่วโมงรายคน → phase 2) |
| **8. Calculation integration** | ต่อ engine เข้ากับ attendees/override | คำนวณ personCourtShare, personShuttleCost, ปัดขึ้น, คำนวณส่วนต่างรวม |
| **9. Summary view** | หน้าสรุปผล | breakdown ต่อคน, ส่วนต่างปัดขึ้น, warning banner ถ้า override เกินยอดจริง |
| **10. Persistence** | บันทึก JSON ลง localStorage | เก็บประวัติ session แบบ structured data |
| **11. QR รับเงิน (static)** | ตั้งค่า + ปุ่มแสดง QR | หน้า Settings อัปโหลดรูป QR ครั้งเดียว, ปุ่มเล็กที่หน้าสรุปเปิด modal |
| **12. Share/export** | ปุ่ม copy ข้อความ + generate รูปใบเสร็จ | ข้อความสำหรับแปะไลน์กลุ่ม, รูป generate สดจาก JSON ตอนกดแชร์เท่านั้น |
| **13. Polish & accessibility** | edge cases + UI standards | 44px tap target, aria-label ทุกปุ่มไอคอน, ฿ ติดตัวเลข, ไม่มีคนถูกเลือก (กันหารด้วย 0), ลบป้ายราคาที่แปะอยู่ในคอร์ทต้องลบออกจากคอร์ทด้วย, mobile responsive test |
| **14. QR แบบฝังยอดเงิน (ขยายทีหลัง)** | generate QR พร้อมเพย์ต่อคนอัตโนมัติ | ใช้ `promptpay-qr` ผูกเบอร์/เลขบัตร + ยอดต่อคน แทน static image |

**แนะนำลำดับ:** Phase 1–11 คือ MVP ที่ใช้งานได้ครบตามที่คุยกันมาทั้งหมด (รวม drag-to-assign ของค่าคอร์ท) Phase 12–13 เพิ่มความสมบูรณ์ก่อนใช้จริง ส่วน Phase 14 เป็นของเสริมทำได้เมื่อมีเวลา
